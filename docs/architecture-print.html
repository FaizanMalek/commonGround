1. Executive Summary

CommonGround is a real-time donation coordination platform for the Greater Moncton Homelessness Steering Committee (GMHSC) network of 28 homeless-serving organizations. It connects donors, shelter staff, and network coordinators in a single web application.

  • Donors — Browse live needs and submit donations without an account.
  • Shelter staff — Manage inventory, post shortages, confirm donations, request surplus, chat.
  • Coordinators — Network-wide KPIs, org/staff management, transfers, exports.

The app runs as a monolithic Node.js process: Express serves static HTML/JS from public/ and REST API under /api, backed by MySQL, with Socket.IO for live updates. No frontend build step, no microservices, no ORM.

7. Frontend Architecture

Multi-page app with two large dashboard SPAs (staff.html, coordinator.html). Shared client code in public/js/api.js (fetch + cookies), i18n.js (EN/FR), theme utilities. Dashboards use sidebar section switching without full page reloads.

9. Authentication & Security

Login verifies bcrypt password against staff_members or admins. JWT access + refresh tokens stored in httpOnly cookies. Coordinator tokens include isAdmin: true.

10. Real-Time Layer (Socket.IO)

Socket.IO shares the HTTP server. Events: donation:new, need:new, need:fulfilled, chat:newMessage.

11. Donation Matching Engine

POST /api/ai/match-donation — rule-based, no external LLM.

FactorPoints
Category match+10
Item name similarity+15
Urgency (critical→low) × 3up to +12
Quantity ≥ need+5

Returns top 3 organizations from all unfulfilled needs network-wide.

13. How Items Are Stored

No global product catalog. Items are org-owned rows with free-text item_name (e.g. "Shelf-Stable Milk (1L)").

ConceptTableUniqueness
Stockinventory_itemsOne row per (org + name + category)
ShortageneedsOne open need per (org + name + category)
DonationdonationsStandalone until matched to one org

If all 28 orgs have milk

  • Inventory: 28 separate rows — independent quantity, status, expiry.
  • Needs: Up to 28 need rows; matcher returns top 3 by score.
  • Transfers: Reference specific inventory_item_id, not global "milk".
  • Confirm donation: Updates only the matched org's inventory row.

Status logic: quantity < target → low; quantity > target → surplus; else available.

14. Domain Workflows

Donation lifecycle

Donor submits → POST /api/public/donations (pending)
  → confirmation email → Socket.IO donation:new
  → POST /api/ai/match-donation → PATCH match (matched)
  → staff confirm → inventory++ → thank-you email
  → coordinator may set delivered

Surplus redistribution

Staff flags surplus → coordinator sees network surplus
Staff B posts need → request surplus OR coordinator initiates transfer
Coordinator approves → transfer tracked → receiving staff completes

Appendix: Design Principles

  1. Monolith simplicity — one process, one deploy.
  2. Org-scoped data — inventory and needs belong to organizations.
  3. Free-text items — flexible naming; fuzzy matching on submit.
  4. Progressive auth — donors need no account.
  5. Real-time dashboards via Socket.IO.
  6. Rule-based matching — no paid AI APIs required.
